# Acceptance Criteria - F126

## Functional
1) 同一品號在「全聯」「7-11」兩通路上傳時各填不同備註，關帳後彙總表第 1 版該品項備註欄顯示按鈕「備註」，點擊後彈窗列出兩行：
   `[全聯/M月] 內容A`、`[7-11/M月] 內容B`（順序依 CHANNEL_ORDER）。
2) 同一品號在排序較前的通路**無備註**、排序較後的通路有備註時，彙總表仍顯示後者備註（回歸測試本次根因）。
3) 贈品預估上傳的備註也會出現在彙總表，標示其通路。
4) 生管於編輯模式修改「7-11」那則備註並儲存為新版本後：
   - 新版本中 7-11 的備註為修改後內容；全聯備註不變。
   - 切回前一版本，備註仍為修改前內容。
5) 匯出 Excel 的備註欄內容與畫面一致，多則以換行分隔於同一儲存格。
6) 無任何備註的品項，備註欄顯示「-」。
7) 已關帳的舊月份彙總表可正常開啟，不報錯（備註可為空，不要求回補）。

## Build / Test
8) `FormSummaryService` 單元測試涵蓋第 1、2、3、4 項情境並通過。
9) 後端既有測試全綠：`docker compose exec backend_server ./gradlew test`
10) 前端 `ForecastListPage` 測試涵蓋備註按鈕、彈窗顯示與編輯模式並通過；既有前端測試全綠。

## Manual Test Steps
1) 建立月份 M，以業務帳號上傳全聯、7-11 預估量 Excel（同品號、不同備註；另一品號只有 7-11 有備註）。
2) 關帳月份 M。
3) 以生管帳號開啟彙總表單，確認第 1、2 項。
4) 進入編輯模式修改 7-11 備註、儲存，確認第 4 項。
5) 匯出 Excel，確認第 5 項。
